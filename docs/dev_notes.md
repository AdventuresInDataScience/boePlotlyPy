# Developer notes

How boePlotlyPy is put together: what each file does, what each function and constant
is for, and what calls what. For using the package, see the [README](../README.md).

## The idea in one paragraph

boePlotlyPy recreates the R package
[boeCharts](https://github.com/bank-of-england/boeCharts) for Plotly. Each Bank of
England chart style is a **Plotly template** registered under a name such as
`"boe_mpr"`. Templates do most of the work: fonts, colours, gridlines, axes, title and
legend placement. Per-chart choices (title, source line, palette, legend position,
zero line and so on) go through **one function, `apply_formatting()`**. Palettes are
**plain data** (`PALETTES`). Everything else is ordinary Plotly.

## What happens on `import boeplotlypy`

1. `__init__.py` imports `palettes`, `effects`, `fonts` and `formatting`.
   `formatting` imports `themes/_boe.py`, which imports `palettes`.
2. A loop at the bottom of `__init__.py` goes through every module in `themes/`
   whose name doesn't start with `_`. For each one it:
   - imports it, which runs the module and builds its `TEMPLATE`. BoE themes call
     `boe_template()`;
   - calls `_match_other_subplots(TEMPLATE)`;
   - registers the template with `plotly.io.templates[NAME] = TEMPLATE`;
   - records the name, and whether the module sets `HIDDEN = True`, in `_THEMES`.

After that, `template="boe_mpr"` works anywhere in Plotly.

## Module reference

### `src/boeplotlypy/__init__.py`

The public API is re-exported here: `apply_formatting`, `PALETTES`, `PALETTE_GROUPS`,
`palettes`, `registered_themes`, `add_glow`, `enable_fonts`, `font_face_css`.

| Name | What it is | Calls | Called by |
|---|---|---|---|
| `_THEMES` | Dict of theme name → hidden flag, in registration order | | Filled by the import loop; read by `registered_themes` |
| `registered_themes(include_hidden=False)` | Names of the registered themes; hidden ones only on request | | Users, `scripts/generate_previews.py`, tests |
| `_match_other_subplots(template)` | Copies a template's background, grid, line and text colours to 3D (`scene`), `polar`, `ternary` and `geo` subplots, which don't inherit the 2D settings. Skips templates without a background | | The import loop |
| Import loop (module level) | Discovers and registers theme modules | `importlib`, `_match_other_subplots` | Runs once on import |

### `src/boeplotlypy/formatting.py`

| Name | What it is | Calls | Called by |
|---|---|---|---|
| `apply_formatting(fig, *, theme, title, subtitle, source, palette, legend, grid, axis, hline0)` | The one function for per-chart formatting. Every argument is optional; `None` keeps the theme's setting. Reads the theme's settings from `fig.layout.template.layout.meta["boeplotlypy"]`, falling back to MPR's for non-BoE templates. Changes `fig` in place and returns it | `palette_colours`, `_recolour`, `legend_layout`, `grid_layout`, `axis_layout`, `ggplot_size`, `_add_source` | Users, `generate_previews.py`, tests |
| `_recolour(fig, colours)` | Recolours traces in one pass. Each series (keyed by `legendgroup` or name, so facets match) gets the next colour. Pie, sunburst and treemap slices get one colour each. Continuous traces and colour axes get `colorscale(colours)`. OHLC, candlestick and waterfall are skipped. Warns if colours run out | `colorscale` | `apply_formatting` (for `palette=`, or `theme=` without `palette=`) |
| `_add_source(fig, text, style)` | Adds the source line as an annotation named `boe_source`, replacing any earlier one. Plotly can only place annotations relative to the plot area, so it estimates the height of the tick labels, axis title and any bottom legend, hangs the text below them, sets the bottom margin to fit, and lifts a bottom legend above the text | `pt` | `apply_formatting` |

### `src/boeplotlypy/themes/_boe.py`

Builds the BoE templates and translates boeCharts' options. The underscore keeps the
loader from treating it as a theme.

| Name | What it is | Calls | Called by |
|---|---|---|---|
| `META_KEY` | `"boeplotlypy"`: the key under `layout.meta` where each BoE template stores its full settings | | `boe_template`, `apply_formatting`, tests |
| `CALIBRI`, `ARIAL` | Font stacks. Calibri falls back to the bundled Carlito | | `DEFAULTS`, `boe_identity`, `boe_mcg`, tests |
| `LEGEND_POSITIONS` | The legend position names accepted everywhere | | `legend_layout`, tests |
| `pt(points)` | Points → pixels (96 dpi) | | `boe_template`, `axis_layout`, `_add_source`, tests |
| `ggplot_size(size)` | ggplot line size → pixels | | `DEFAULTS`, `boe_mpr`, `boe_mcg`, `apply_formatting`, tests |
| `DEFAULTS` | Every setting a BoE theme can change, with boeCharts' `theme_mpr()` values. Comments describe each one. `None` colours fall back to `text_colour` | | `boe_template` |
| `_letters(spec)` | Normalises a boeCharts grid/axis value (`"X"`, `"XY"`, `True`, …) to letters; rejects anything else | | `grid_layout`, `axis_layout` |
| `grid_layout(grid, colour, width)` | `(xaxis, yaxis)` gridline settings. **boeCharts' convention: `"X"` means horizontal lines.** Widens lines to at least 1px | `_letters` | `boe_template`, `apply_formatting` |
| `axis_layout(axis, colour, width, ticks, tick_length, box)` | `(xaxis, yaxis)` axis line and tick settings; `box=True` draws a border round the plot area. Widens lines to at least 1px | `_letters`, `pt` | `boe_template`, `apply_formatting` |
| `legend_layout(position, orientation)` | `layout.legend` settings for a named position. Top legends sit above the plot area; bottom legends at the bottom of the figure (`yref="container"`) | | `boe_template`, `apply_formatting`, tests |
| `boe_template(name, overrides)` | Merges `overrides` into `DEFAULTS`, resolves `None` colours, builds the `go.layout.Template`, and stores the merged settings in `layout.meta[META_KEY]` | `palette_colours`, `colorscale`, `grid_layout`, `axis_layout`, `legend_layout`, `pt` | Each `boe_*.py` module, tests |

### `src/boeplotlypy/themes/boe_*.py`

Each defines `NAME` and `TEMPLATE = boe_template(NAME, {...settings that differ from DEFAULTS...})`.
The docstring says which boeCharts function it matches and what it looks like.

| Module | boeCharts | Default palette | Notes |
|---|---|---|---|
| `boe_mpr.py` | `theme_mpr()` | `boe` | Also exposes `STYLE`, its overrides dict, which `boe_fsr` reuses |
| `boe_fsr.py` | `theme_fsr()` | `fsr` | `{**boe_mpr.STYLE, "palette": "fsr"}`: identical look in boeCharts |
| `boe_overground.py` | `theme_overground()` | `boe_highlights` | boeCharts' 3-colour `boe_overground` palette is a subset of it |
| `boe_identity.py` | `theme_boe_identity()` | `boe_identity` | Horizontal legend (R's vertical one crowds the plot); aqua sequential scale |
| `boe_mcg.py` | `theme_mcg_pub()` | `mcg` | Legend at the bottom, source line right-aligned |

### `src/boeplotlypy/palettes.py`

| Name | What it is | Calls | Called by |
|---|---|---|---|

| Name | What it is | Calls | Called by |
|---|---|---|---|

### `src/boeplotlypy/fonts/__init__.py`

| Name | What it is | Calls | Called by |
|---|---|---|---|
| `FONTS_DIR` | Path of the bundled `.ttf` files | | `font_face_css`, tests |
| `FONT_FILES` | Font family → `[(filename, weight, style)]`. Carlito is the BoE one; the rest serve hidden themes | | `font_face_css`, tests |
| `font_face_css()` | `@font-face` CSS with every bundled font embedded as base64 (cached) | | `enable_fonts`, users |

Fonts only reach a renderer that has them. Browsers get them via `enable_fonts()`;
static export with kaleido needs the `.ttf` files installed on the OS. Calibri (MPR,
FSR, Overground) is Microsoft's and can't be bundled, so the font stack falls back to
Carlito, which has the same metrics.

## Tests

```bash
uv run pytest                     # everything, about a minute
uv run pytest -m "not render"     # skip tests that need a browser
uv run pytest -m visual --update-baselines   # after an intended visual change
BOECHARTS_DIR=<checkout> uv run pytest       # also compare palettes with boeCharts
```

Markers (set in `pyproject.toml`): `render` tests draw figures with plotly.js through
kaleido, which needs Chrome or Edge. `visual` tests compare renders with
`tests/baseline/*.png`.

| File | Covers |
|---|---|
| `conftest.py` | `CHARTS` (about 35 chart builders, each flagged if its series take palette colours), `DATASETS` (16 awkward data shapes), sample data frames, the `--update-baselines` option, and fixtures that start one shared kaleido browser when `render` tests run. **Add a chart type or dataset here and every matrix test picks it up** |
| `test_palettes.py` | Palette structure and values against boeCharts, read-only access, lookup errors, Lab conversion against reference values, colourscales; optional comparison with a boeCharts checkout |
| `test_boe_themes.py` | Each BoE template matches its settings; per-theme looks (grid, axes, title, legend); `pt`/`ggplot_size`; `grid_layout`/`axis_layout`/`legend_layout` tables; building a custom theme |
| `test_formatting.py` | Each `apply_formatting` argument in isolation, including edge cases (repeat calls, user annotations kept, too-short palettes, facets) |
| `test_matrix.py` | Every theme × every chart type, with and without all arguments; every theme × every dataset; legend positions × themes × charts; repeat calls change nothing; rendered checks of fonts, background, title, legend and zero line |
| `test_visual.py` | Each theme's line and bar chart compared pixel by pixel with the baselines (1% tolerance); differences saved to `tests/visual_output/` |
| `test_themes.py` | Every registered theme, hidden ones included: registers, is valid, has a colourway; hidden themes are usable but not listed |
| `test_extras.py` | `add_glow` and the font helpers |

## Hidden themes

The package started as a copy of a fun theme collection (`plotly-themes`). Its 22
themes are kept as **easter eggs**: `matrix`, `cyberpunk`, `star_wars`, `star_trek`,
`synthwave`, `blueprint`, `financial_times`, `lego`, `coke`, `barbie`,
`vintage_comic`, `xkcd`, `newsprint`, `minecraft`, `nasa`, `gameboy`, `tableau`,
`powerbi`, `nike`, `amber_terminal`, `nord` and `dracula`.

- Each is a plain `go.layout.Template` in `themes/<name>.py` with `HIDDEN = True`.
  They don't use `_boe.py`.
- They are registered like any other theme, so `template="cyberpunk"` and
  `apply_formatting(fig, theme="cyberpunk")` work. They are left out of
  `registered_themes()` (unless `include_hidden=True`) and are not mentioned in the
  README.
- Several use bundled novelty fonts (see `fonts/NOTICE.md`), and three look best with
  `add_glow()`. Brand fonts that can't be redistributed (LEGO, Coca-Cola) were removed;
  those themes list them first in their font stacks and use them only if installed.
- `test_themes.py` checks them; `generate_previews.py --legacy` previews them.
- To hide another theme, add `HIDDEN = True`. To remove one, delete its module and its
  preview image.

## Choices worth knowing

- **Matching boeCharts.** Option names and values follow boeCharts where one exists
  (`grid="X"`, `legend` positions, `hline0`). Deliberate differences:
  - `vibrant_h` uses `rich_orange`, because boeCharts references a missing colour and
    silently drops it;
  - the identity theme's legend is horizontal;
  - lines are at least 1px wide;
  - Plotly's subtitle sits a fixed distance below the title, slightly further than in
    R.
- **Why the style is stored in the template.** `apply_formatting` needs the theme's
  caption colour, tick settings and so on. Storing them in `layout.meta` means they
  travel with the figure, including when the theme was set with
  `pio.templates.default`.
- **Why `theme=` recolours.** Plotly Express writes colours into each trace when it
  builds a figure, so switching template afterwards wouldn't change them.
- **The source line is estimated.** See `_add_source`. If axis titles or the figure
  height change after `apply_formatting`, call it again.
- **Minimum versions.** `plotly>=5.23` is needed for `title.subtitle`. Rendering tests
  use kaleido 1.x, which drives an installed Chrome or Edge.

## Common tasks

- **Add a palette:** add an entry under its group in `_DEFINITIONS` (`palettes.py`).
- **Add a BoE theme:** create `themes/boe_<name>.py` with
  `NAME = "boe_<name>"` and `TEMPLATE = boe_template(NAME, {...})`. Then add it to
  `BOE_THEMES` and the per-theme table in `test_boe_themes.py`, run
  `uv run pytest -m visual --update-baselines` to create its reference images, and run
  `scripts/generate_previews.py`.
- **Add a theme setting:** add it to `DEFAULTS` with a comment, use it in
  `boe_template`, and override it in the themes that need it.
- **Add an `apply_formatting` argument:** add it to the signature and docstring,
  handle it in the function body, add tests in `test_formatting.py`, and add it to
  `ALL_ARGS` in `test_matrix.py` and to the README's argument table.
- **Check palettes against a newer boeCharts:** clone it and run
  `scripts/check_against_boecharts.py <clone>`.
